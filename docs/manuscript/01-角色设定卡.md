# 角色设定卡 · 八人

> **性质声明**：全部为化名虚构角色，构造原则是"每个人都有独立的 KPI 和独立的恐惧，对话时立场不可互换"。写作时若一段话套到另一人嘴里也成立，说明角色没立住，重写。

---

## ① 我（主角）——工程效能与架构组负责人

| 维度 | 内容 |
|------|------|
| 本名 | 全书不出现真名，第一人称"我" |
| 职位 | 工程效能与架构组负责人（治理组负责人） |
| 经验 | 8 年，做过交易核心与风控引擎 |
| 立场 | AI 是杠杆，但杠杆必须有支点——支点就是契约、测试、留痕 |
| 口头禅 | "先画边界，再让 AI 动手。" |
| 恐惧 | 成为"AI 化"失败的替罪羊：上面要效率，下面要自由，出事算我的 |
| KPI | 治理覆盖率、事故率下降、契约一致率 |
| 与其他角色的张力 | 夹在老陈（要 ROI）、林工（要零损失）、阿杰（要自由）、周姐（要士气）之间，谁都得罪不起 |
| 弱点 | 倾向用流程解决问题，被周姐批评"把人当机器管" |
| 代表性场景 | 2024-06-05 被任命时第一反应是拒绝；2025-03-13 把契约签字权让给小王 |

---

## ② 老陈（CTO）

| 维度 | 内容 |
|------|------|
| 职位 | CTO，技术出身，CEO 信任 |
| 立场 | 支持 AI，但绝不愿替事故背书 |
| 口头禅 | "我不关心你用不用 AI，我关心出事谁负责。" |
| 恐惧 | 在董事会上被问"AI 投入 ¥480 万，回报在哪"答不上来 |
| KPI | 系统稳定性（可用性 ≥ 99.95%）、研发效率（人均交付） |
| 决策风格 | 给资源、给授权，但要结果、要责任人 |
| 与主角的张力 | 既要主角推进治理，又在事故后第一个追问主角责任；给 4 个人头但只批 5/8 |
| 代表性场景 | 2024-05-30 双周会一问立项；2025-08-14 大会点名主角复盘 |

---

## ③ 林工（风控负责人）

| 维度 | 内容 |
|------|------|
| 职位 | 风控负责人，10 年风控经验 |
| 权力 | 一票否决权 |
| 立场 | 资金链路绝不让 AI 碰；AI 生成的代码必须人审 |
| 口头禅 | "这笔钱错了，用户不会找 AI，会找我。" |
| 恐惧 | 有一天对账差额出现在自己签字的链路上 |
| KPI | 资金零损失、风控拦截准确率 |
| 与主角的张力 | 表面配合治理，实际把 AI 圈在资金链路之外；D-0114 后彻底站到对立面 |
| 对话指纹 | 永远从"能不能验证"切入，验证不了就否决 |
| 代表性场景 | 2024-04-22 要清单拿不出；2025-01-16 复盘会拍桌 |

---

## ④ 小王（多端 TL）

| 维度 | 内容 |
|------|------|
| 职位 | 多端 TL，负责安卓 + 鸿蒙 + 小程序 |
| 经验 | AI 重度用户，但在 B-0527 吃过大亏 |
| 立场 | AI 可以写代码，但**绝不能改契约**——契约一动五个端都要发版 |
| 口头禅 | "AI 改一次接口，三个端要发版，谁扛？" |
| 恐惧 | 凌晨被叫起来排查"为什么只有小程序炸了" |
| KPI | 多端一致性、发版准时率、端侧崩溃率 |
| 与主角的张力 | 从受害者变成权力方：E-0311 后要求并拿到了破坏性契约变更的一票签字权，分走了主角的审批权 |
| 对话指纹 | 永远问"它怎么验证的"，并把"端"挂在嘴边 |
| 代表性场景 | 2025-02-20 主导多端契约同步；2025-03-13 拿到签字权 |

## ⑤ Lily（合规负责人）

| 维度 | 内容 |
|------|------|
| 职位 | 合规负责人，法务背景，不懂代码 |
| 立场 | AI 生成代码必须留痕，否则审计追溯不了，就不合规 |
| 口头禅 | "审计问起来，我能拿出一份 AI 操作记录吗？" |
| 恐惧 | 监管来查，发现某段代码"不知是谁、用了什么 prompt 生成" |
| KPI | 合规零缺陷、审计通过率 |
| 与主角的张力 | 不关心技术好坏，只关心"能不能解释"；F-0515 直接叫停灰度 |
| 对话指纹 | 不停追问"谁审的""记录呢"，直到对方答不上来 |
| 代表性场景 | 2024-08-08 推动 prompt 归档；2025-05-15 否决灰度 |

---

## ⑥ 阿杰（一线工程师）

| 维度 | 内容 |
|------|------|
| 职位 | 一线工程师，3 年经验，AI 重度用户 |
| 立场 | AI 让他一个人顶一个半人，反对一切拖慢提交的治理 |
| 口头禅 | "你们治理组的流程，比我写代码时间还长。" |
| 恐惧 | 被"监控式治理"判定为低效，绩效受影响 |
| KPI | 需求交付量（他只认这一个） |
| 与主角的张力 | 治理的直接受害者；2025-05-22 因"被监控感"离职，是全书的代价之一 |
| 对话指纹 | 用"现在就要上线"对抗一切"先填契约" |
| 代表性场景 | 2024-07-03 公开吐槽边界清单；2025-05-22 离职面谈 |

---

## ⑦ 老张（SRE 负责人）

| 维度 | 内容 |
|------|------|
| 职位 | SRE 负责人，看监控过日子 |
| 立场 | 不关心 AI，只关心回滚速度和告警质量 |
| 口头禅 | "出事的时候，AI 能帮我回滚吗？" |
| 恐惧 | 一个 AI 引入的 bug，监控根本没覆盖，炸了才知道 |
| KPI | 可用性、MTTR（平均恢复时间） |
| 与主角的张力 | 既受益于治理（事故少了），又被治理流程拖慢应急；和林工在"叫停 vs 回滚"上偶尔冲突 |
| 对话指纹 | 用"指标"说话，一句话离不开 SLI/SLO |
| 代表性场景 | 2025-01-14 D-0114 告警立功；与林工在叫停节奏上的分歧 |

## ⑧ 周姐（HRBP）

| 维度 | 内容 |
|------|------|
| 职位 | HRBP，关心士气、离职率、绩效公平 |
| 立场 | AI 治理不能变成"监控工程师" |
| 口头禅 | "你让 AI 记录每个人的 prompt，工程师会觉得被监控。" |
| 恐惧 | 治理把优秀工程师逼走，离职率背到她头上 |
| KPI | 离职率、满意度、绩效公平性 |
| 与主角的张力 | 每次主角加强留痕，周姐就来谈"边界"；阿杰离职后压力最大 |
| 对话指纹 | 反问"你怎么保证"，逼主角承认"还没想好" |
| 代表性场景 | 2024-08-29 prompt 匿名化；2025-05-22 阿杰离职后找主角谈话 |

## 对话风格速查（写对话前先对指纹）

- **林工**：能不能验证？不能 → 否决。
- **小王**：它怎么验证的？端怎么办？
- **Lily**：谁审的？记录呢？补上。
- **阿杰**：我现在就要上线。
- **老张**：指标说话，能回滚吗？
- **周姐**：你怎么保证不变成监控？
- **老陈**：出事谁负责？回报在哪？
- **我**：先画边界，再让 AI 动手；但"边界怎么落地到 CI"我经常答不全。

> **写作铁律**：写完一段对话，把名字遮住，能猜出是谁说的才算过。
