# 作者素材采集清单

> 本页是**给作者的，不是给读者的**。提高证据密度时按此清单收集；AI 只能从素材里提取故事，不能凭空编造。

## 已由公开来源覆盖（无需你再提供）

以下外部锚点已在 [公开证据档案](public-evidence.md) 核实并写入理论章「公开参照」：

- DORA 2025「AI 是放大器」
- DORA 信任 / AUP / 快速反馈策略
- DORA 准确率之外的顾虑（隐私、技能退化、沙箱等）
- NIST AI RMF 1.0 与 GenAI Profile
- GitHub × Accenture 企业 RCT（PR/合并率/构建）
- Michael Nygard ADR（2011）

**仍必须由你补的**只有：本组织脱敏真实片段（事故、PR、账单、访谈）。没有也可先发布——四案例已声明为示范叙事。

## 每章最低素材包（若你要补真实层）

| 类型 | 要求 | 脱敏建议 |
|---|---|---|
| 一手案例 | 1 个真实项目片段（PR / 事故 / 设计会） | 去公司名、域名、密钥；保留结构与决策点 |
| 失败案例 | 1 次返工 / 误删 / 过拟合 / 越权 | 保留时间线与代价数字（可区间化） |
| 度量数据 | 1 组前后对比（时长 / 事故率 / 成本） | 标单位与时间窗；写不清就标 `[待验证]` |
| 可操作清单 | ≥5 条 checklist | 必须可勾选、可执行 |
| 配图 | ≥1 张 Mermaid | 术语与 GLOSSARY 一致 |
| 外部引用 | ≥3 条可点开的公开来源 | 标题、机构、年份、链接；不能确认勿写 |

## 优先采集顺序

1. **资金 / 精度相关事故**（案例一、二叙事的骨架）
2. **AI 生成代码的 Git 痕迹**（commit message、PR 描述、review 评论）
3. **工具账单与效能前后**（Copilot / Cursor 费用、人均提交、评审时长）
4. **治理会议纪要脱敏版**（谁反对、为什么、最后怎么妥协）
5. **Beta 读者反馈**（哪里假、哪里看不懂、哪里想跳过）

## 贴素材时的硬规则

- 禁止真实密钥、内部 URL、未脱敏客户名。
- 数字若与 `02-数字清单.md` 冲突，以清单为准或同步改清单。
- 公开竞品 / 监管事件必须能点开核实；否则标 `[待核实]`。

## AI 在素材上的正确用法

1. 从时间线提取冲突与决策点
2. 把操作片段改写成步骤与反模式
3. 把数字整理成对照表与度量节
4. **不要**生成「听起来真实」的外部案例
