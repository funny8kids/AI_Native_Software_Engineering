# GLOSSARY — 全书术语表

> 唯一术语权威。正文、图、侧边栏、附录必须与本表一致。新增术语先改本表。

| 术语 | 英文 | 定义（本书用法） | 禁止混用 |
|---|---|---|---|
| AI 原生 | AI-native | 围绕「AI 会失灵」重新设计工程流程与责任结构；不是把 AI 塞进旧流程 | 不等于 AI 辅助、AI 编码、Copilot |
| AI 辅助 | AI-assisted | 流程不变，AI 帮人完成单点任务（补全、单测、解释） | 不可写成 AI 原生 |
| 上下文工程 | context engineering | 把契约、依赖、约束、历史、权限组织成模型可消费的上下文 | 不等于「多贴代码」 |
| 智能体 | agent | 具备工具调用与多步执行能力的模型封装；能行动，但仍不扛责 | 不是「数字员工」 |
| 评估 | eval | 对生成结果做可重复度量的检查（契约测试、回归、对账、人工抽检） | 不等于「看一眼」 |
| 护栏 | guardrail | 自动阻止或降级越权 / 越界输出的机制（门禁、权限、熔断） | 不是道德说教 |
| 人在回路 | HITL | 在关键节点由人选择、签字、负责；生成可自动，生效须人批 | 不是「有人看着」 |
| 可观测性 | observability | 能从外部状态推断内部行为：日志、指标、追踪、审计痕迹 | 不等于「有监控大盘」 |
| 提示词腐化 | prompt rot | 提示词与真实契约 / 组织约束脱节后，输出持续劣化且无人察觉 | 不是「模型变笨了」 |
| 契约 | contract | 接口 / 数据 / 行为的事实声明，先于实现存在，可被机器验证 | 不等于接口文档截图 |
| 留缝 | leave seams | 在 AI 输出与实际生效之间保留人工缝隙与可回滚点 | 不是「代码留 TODO」 |
| 留痕 | leave traces | 每次生成、审批、变更留下可审计记录（prompt、PR、ADR、对账单） | 不是「聊天记录」 |
| 门禁 | gate | 上线 / 合并前不可绕过的自动或人工检查层 | 不等于「建议」 |
| 对账 | reconciliation | 对资金、精度、余额、策略意图做独立核对 | 不是单元测试 |
| 遗留债务 | open questions | 章内提出、由后章回答的未决问题 | 不是 TODO 列表 |
| 四案例 | four cases | 电商平台 / 交易所 / 量化基金 / 安全初创，等权虚构脱敏示范 | 不指代真实公司 |
| 边界清单 | AI boundary list | 声明 AI 可碰 / 需审批 / 不可碰的组织级清单 | 不是工具白名单 |
| 介入点矩阵 | intervention matrix | 规定「谁必须在哪一步接手」的责任表 | 不是 RACI 全集 |
| 幻觉 | hallucination | 模型输出看似合理但与事实 / 契约 / 运行时不一致 | 不限于「编造引用」 |
| 灰度 | canary / gradual release | 分层放量、可自动刹车、可回滚的发布策略 | 不等于「先发 1% 再说」 |
| 契约先行 | contract-first | 接口事实声明先于代码；实现必须能对上契约仓库 | 不是「先写 OpenAPI 再抄」 |
| 组织接管 | org takeover | 在 AI 失灵点建立人、流程、度量与问责 | 不是「加个审批流」 |

## 使用约定

1. 首次出现可加英文；后文只用中文短名。
2. 事故编号（A-0402、D-0114 等）保留原样，不翻译。
3. 工具名（Copilot、Cursor、import-linter、Flyway 等）保留产品名，不写成「某工具」。
4. 「组织接管」是全书主语之一，不要缩写成「治理」两字带过——治理是机制，接管是动作。
